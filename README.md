# Moto G7 Play (channel) — build repository

This repository contains the integrated build for the Motorola Moto G7 Play (`channel`) and separated component workflows for rootfs, kernel, DTBO, and lk2nd.

## Integrated build on `main`

`.github/workflows/build.yml` is the complete build flow.

A single run builds and validates:

- the Channel mainline kernel, DTB, and modules;
- lk2nd for MSM8953/SDM632;
- the minimal Channel DTBO;
- Debian Trixie rootfs and initramfs;
- `boot-channel.img`;
- final hashes and source/build reports.

The main output artifact is `channel-mainline-debian`.

### Files in `channel-mainline-debian`

- `boot-channel.img` — final boot image packed by the integrated workflow.
- `lk2nd-msm8953.img` — lk2nd image built for the Channel-compatible target.
- `dtbo-motorola-channel.img` — minimal DTBO produced for the Channel flow.
- `Image.gz` — compressed ARM64 kernel image.
- `Image.gz-dtb` — kernel image concatenated with the Channel DTB.
- `*.dtb` — compiled Channel device tree.
- `initrd.img-*` — initramfs generated for the same kernel release.
- `debian-channel-rootfs.ext4.zst` — compressed Debian ext4 rootfs image.
- `kernel-modules-*.tar.zst` — module tree matching the built kernel release.
- `kernel.config` — final integrated kernel configuration.
- `System.map` — symbol map for the built kernel.
- `kernel-release.txt` — exact kernel release string.
- `source-report.txt` — selected kernel source/ref information and build review data.
- `lk2nd-commit.txt` — exact lk2nd commit used.
- `dtbo-lk2nd-commit.txt` — exact DTBO source commit used.
- `build-info.txt` — rootfs build metadata.
- `SHA256SUMS*` — hashes generated by the workflow.

The main artifact is retained for 14 days.

If the integrated build has no `SSH_PUBLIC_KEY` secret, its current rootfs flow can also publish `channel-ssh-test-key` containing the generated test key. That credential artifact is retained for 1 day.

## Separated builds

The repository also has dedicated component branches:

| Branch | Workflow | Main artifact |
| --- | --- | --- |
| `rootfs` | `Build Debian rootfs` | `channel-debian-rootfs` |
| `kernel-mainline-7.1` | `Build kernel mainline 7.1` | `channel-kernel-mainline-7.1` |
| `dtbo` | `Build channel DTBO` | `channel-dtbo` |
| `lk2nd` | `Build lk2nd MSM8953` | `channel-lk2nd-msm8953` |

The same component workflow files are exposed on `main` so GitHub shows their manual **Run workflow** controls. Those launchers check out the corresponding component branch before building.

## Recent project changes

The component builds were separated without removing the known integrated build from `main`.

The separated `rootfs` workflow was later extended with selectable SSH authentication inputs and optional generated credential artifacts. Those options belong to the separated rootfs workflow; they do not replace the behavior of the integrated `build.yml`.
